# Sa_displacedge for YMM4 — 0.1.0 (Mirage Edge / 蜃気楼エッジ)

輪郭(エッジ)を液状ガラスのように屈折・変位させるYMM4用エフェクトです。輪郭検出は行いますが、Sa_aohueのように色を変えるのではなく、**輪郭に沿って画素そのものを渦状にずらし**、色収差(プリズム縁取り)と薄膜干渉風の虹色ハイライトを重ねます。既存の「変位マップ」「色収差」「グリッチ」のどれとも異なる、輪郭ガイド付きの液体屈折エフェクトです。

## 1. アルゴリズム

Sa_aohueのYMM4実装(OKLab線検出 → GPUガウシアンで場を拡張 → 合成、という2段構成)を参考に、輪郭を「色を変える」のではなく「変位させる」方向に発展させています。

1. **輪郭検出**(`EdgeGradient.hlsl`): OKLab Lに対しScharr勾配を`検出サイズ`間隔でサンプリングし、勾配ベクトル(gx, gy)と大きさを求める。アルファで重み付けした`(gx·a, gy·a, mag·a, a)`として出力する(Sa_aohueのChromaFieldと同じ、分子・分母を運ぶ手法)。
2. **場のぼかし**(D2DのGaussianBlur、`変位範囲`をσに使用): 二値化する前に生の勾配場をぼかすことで、輪郭同士が近接する部分で方向が打ち消し合い、輪郭からの距離に応じてなめらかに減衰する「変位の届く範囲」が得られる。ぼかし後に`(gx·a, gy·a, mag·a, a)`を`mag/a`で割って平均勾配・平均強さを復元する。
3. **しきい値・コントラスト**: 平均強さに`検出しきい値`でしきい値を掛け、`コントラスト`でガンマ補正して0〜1の`mask`を得る(Sa_aohueと同じ`Cavity^(1/Contrast)`の考え方)。
4. **渦ノイズ(カール・ノイズ)**(`FlowDisplace.hlsl`): 回転オクターブ付きの値ノイズfBmの解析勾配から、発散ゼロ(渦のみで湧き出し・吸い込みがない)なベクトル場を`v = (∂ψ/∂y, -∂ψ/∂x)`として作る。旧実装のように4方向の有限差分でfBmを再評価せず、1回の解析勾配評価で済ませるため、乱流の複雑さを上げたときの計算量を抑えられる。`乱流の複雑さ`がオクターブ数、`渦の大きさ`が渦の空間スケール、`流速`がアニメーション速度。ノイズを評価する時間は`animTime = time × 流速 + 位相`(`time`はフレーム番号)で、`位相`は`流速`に関係なく渦の開始位置を一定量ずらす。`シード`(ノイズ座標そのものへのオフセット、別パターンになる)とは別軸のパラメータで、`位相`は同じパターンの「どの時点か」だけを動かす。
5. **流れの合成**: 輪郭の勾配方向(外向き)と渦ノイズを`乱流`で線形補間し、正規化した流れベクトルに`変位強度 × mask`を掛けて最終的な変位量を得る。
6. **色収差サンプリング**: S_DistortChromaの考え方に合わせ、元画像をまず流れベクトルで変位させ、その位置から輪郭勾配方向へ`色収差ステップ数`回スイープしてサンプリングする。赤側・青側のワープ量は`赤ワープ`/`青ワープ`で独立に指定でき、`色収差方向`で勾配方向を回転できる。各タップは赤端〜青端の符号付きワープを持ち、赤・緑・青それぞれのガウス応答(`SpectrumWeight`、中央t=0.5付近で緑・両端でR/Bが強くなる)で重み付けして加算・正規化する。`色収差`は0〜800%で、100%を超えるとRGBサンプル間の分離距離が拡大する。境界はReflectサンプリングで折り返すため、高倍率でも端が単色に潰れにくい。`色収差ステップ数=3`なら3色の端点サンプルに近く、値を上げるほど滑らかなスペクトルになる(その分1ピクセルあたりのテクスチャフェッチが増える)。
7. **虹色ハイライト**: 輪郭の法線と`光の角度`の内積からリムライトを求め、局所的な位相(強さ・時間・渦ノイズ由来)をIQ風コサインパレットに通した虹色を、`虹色の強さ`とリムライト・maskで重み付けして加算する。

### なぜ「発散ゼロ」の渦ノイズか

ただのPerlinノイズの勾配をそのまま変位に使うと、局所的に画素が集まって薄くなったり(吸い込み)、逆に伸びて破れたり(湧き出し)します。カール・ノイズ(スカラー場の回転)は数学的に発散ゼロなので、変位場が「渦を巻くだけ」で吸い込み・湧き出しが起きにくく、液体やガラスが輪郭に沿って渦を巻きながら流れているような見た目になります。回転オクターブ(各オクターブでノイズ座標を回転してから重ねる)は、格子軸に沿った縞模様が出るのを防ぐためです。

## 2. Sa_aohueとの関係

- **共通する設計**: OKLab Lからの輪郭検出、D2Dカスタムシェーダーエフェクトを`GaussianBlur`などの標準エフェクトと繋いだマルチパスグラフ、`(値·alpha, alpha)`の重み運びによるぼかしの正しい平均化、`Threshold`→`Contrast`ガンマという2段階のマスク整形。これらはSa_aohueのYMM4実装(`SaAohueProcessor.cs`, `ChromaField.hlsl`, `Composite.hlsl`)の構成をそのまま踏襲しています。
- **異なる点**: Sa_aohueは輪郭に沿って**色(彩度・輝度・色相)**を変えますが、Sa_displacedgeは輪郭に沿って**画素の位置そのもの**を変位させます。そのため新たに(a)発散ゼロの渦ノイズによる流体的な変位場、(b)輪郭勾配基準の色収差サンプリング、(c)薄膜干渉風の虹色ハイライトを追加しています。輪郭検出もDoG(2スケール円盤ブラーの差)ではなくScharr勾配を使っており、色ではなく「向き」が必要なため独自実装です。
- **S_DistortChromaとの比較**: S_DistortChromaはLens入力の輝度勾配で色ごとのワープ方向を作り、Amount、Blur Lens、Warp Red/Blue、Steps、Wrapなどでプリズム状の色収差を制御します。本実装はLensを入力画像のOKLab L輪郭場から自動生成し、Amount相当を`変位強度`×`色収差`、Blur Lens相当を`変位範囲`、Warp Red/BlueとRotate Warp Dirを同名UIで提供します。さらに輪郭に沿う渦変位と虹色ハイライトを合成するため、S_DistortChromaの完全な置き換えではなく、同じ色収差モデルを内包した拡張です。

## 3. 実装ファイル

- `Shaders/Common.hlsli`: sRGB/OKLab変換、値ノイズ・解析勾配fBm・カール・ノイズ、虹色パレット。`prototype/preview.py`と同じ式。
- `Shaders/EdgeGradient.hlsl` (D2D_INPUT_COUNT=1): Scharr勾配抽出。
- `Shaders/FlowDisplace.hlsl` (D2D_INPUT_COUNT=2): 渦ノイズ合成・変位・S_DistortChroma風の色収差・虹色ハイライト。
- `EdgeGradientEffect.cs`, `FlowDisplaceEffect.cs`: D2Dカスタムシェーダーエフェクトのラッパー(`D2D1CustomShaderEffectBase`)。
- `SaDisplacedgeEffect.cs`: YMM4の`VideoEffectBase`実装、UI定義。
- `SaDisplacedgeProcessor.cs`: `IVideoEffectProcessor`実装、エフェクトグラフの構築と`Update`でのパラメータ反映。
- `ShaderResourceLoader.cs`: 埋め込みリソースからコンパイル済み`.cso`を読む。
- `tests/ReferenceMath.cs`, `tests/DisplacedgeKernelTests.csproj`: 値ノイズ・解析勾配・カール・ノイズの回転構造・`SpectrumWeight`をGPU無しで検証する移植版(本番コードからは参照されない)。

## 4. プロトタイプ(事前検証)

`../prototype/preview.py`はNumPyでの参照実装で、GPU/Direct2D無しでアルゴリズムを事前に見た目確認できます。実装前にこのスクリプトでパラメータを検討し、`../tests/test_prototype.py`で以下を数値検証しています(実行結果はいずれもPASS)。

- 移動窓平均(3回ボックスブラーでガウシアン近似、Sa_aohueのRadiusぼかしと同じ手法)の正規化・恒等性・総和保存。
- Scharrカーネルのタップ総和がゼロ(平坦領域で勾配ゼロ)。
- **解析勾配とカール・ノイズの回転構造**: fBmの解析勾配が独立な有限差分近似と一致し、`v=(dy,-dx)`の回転になっていることを検証します。これにより、4方向のfBm再評価を1回の勾配評価へ置き換えた最適化の数式契約を保ちます。
- バイリニアサンプリングの整数座標での恒等性・境界クランプ。
- 虹色パレットの出力範囲・チャンネル間の位相ずれ。
- 変位強度0のときcomposite出力が入力とほぼ一致すること(`色収差ステップ数`の値によらない)。
- **`色収差ステップ数`のスペクトル応答**(`SpectrumWeight`): 出力範囲が0〜1、外側(t=1)で赤・中央(t=0.5)で緑・内側(t=0)で青が最大になること(ステップ数3のときに旧来のR/G/B順と一致する条件)。ステップ数を増やすほど結果が収束すること(64ステップと128ステップの出力がほぼ一致)。
- **`位相`が`流速×時間`を進めるのと等価であること**: `flow_speed=1`のとき`(time=T, phase=0)`と`(time=0, phase=T)`が画素単位で完全一致すること(`anim_time = time × flow_speed + phase_offset`という単一の合成値でしか使われないため)。`位相`を変えると実際に出力が変わること(0との比較)も検証しています。

**注意**: `preview.py`の`--time`は秒単位ですが、実際のシェーダー(`FlowDisplace.hlsl`)はフレーム番号をそのまま時間入力として使います(YMM4の`FPS`型に依存しない単純な実装のため)。両者は同じ数式で動きますが、同じ`--time`値・同じフレーム番号が同じ見た目になることは意図していません — アルゴリズムの一致を検証する場であり、数値の一致を保証する場ではありません。`位相`(`--phase-offset`)も同様に、両者で単位は共通の数式内(`time × flow_speed + phase_offset`)にとどまり、Python側の秒単位・シェーダー側のフレーム単位という違いは変わりません。

## 5. ビルド・インストール

GitHub Actionsの「YMM4 build」は公式YMM4 LiteのDLLを参照し、Windows SDKのfxcで2つのシェーダーをコンパイルします。成功した実行のArtifactsから`SaDisplacedgeYmm`をダウンロードできます。

.NET 10 SDK、YMM4のDLLフォルダ、Windows SDKのfxc.exeとd2d1effecthelpers.hlsliを指定してローカルビルドする場合:

```powershell
dotnet build ymm/SaDisplacedgeYmm.csproj -c Release "-p:YMM4DirPath=C:\path\to\YMM4\" "-p:FxcPath=C:\path\to\fxc.exe" "-p:D2DIncludePath=C:\path\to\sdk\um"
./ymm/check-shaders.ps1 -FxcPath C:\path\to\fxc.exe
```

生成された`SaDisplacedgeYmm.dll`をYMM4の`user/plugin/SaDisplacedgeYmm/`へコピーし、YMM4を再起動します。

## 7. 既知の制約

- 渦ノイズはScharr勾配同様、幾何・奥行きを一切見ません。輪郭密度から擬似的に「液状化しやすい場所」を作るイラスト的な効果です。
- `変位強度`、`色収差`、`赤ワープ`/`青ワープ`を大きくすると、`FlowDisplaceEffect`が要求する入力ハロー(`Strength × (1 + Dispersion × max(|WarpRed|, |WarpBlue|))`)が大きくなり、GPU負荷とタイル境界での再計算コストが増えます。
- `乱流の複雑さ`(オクターブ数)を上げるほど1ピクセルあたりのノイズ評価回数が増えます(最大8オクターブ)。解析勾配化で旧実装のカール4方向分のfBm再評価はなくなりましたが、重い設定では下げてください。
- `色収差ステップ数`を上げるほど1ピクセルあたりのテクスチャフェッチが線形に増えます(最大128)。滑らかさと引き換えにGPU負荷が上がるので、必要な滑らかさが出る範囲で下げてください。
- HDR素材でのふるまい、非sRGBワークスペースは未対応です。入力はsRGB前提です。

## 色収差の軽量モード

「色収差の品質」で「軽量（最大8サンプル）」を選ぶと、色収差の計算を最大8回の参照に集約します。元の色の重みを保持しますが、細かい模様や大きな変位では見た目が変わるため、その場合は「標準」を使用してください。既定は標準です。128ステップ時の色収差参照回数は16分の1になりますが、YMM4全体の10倍高速化を保証するものではありません。計測結果は `docs/FAST_SAMPLING.md` に記載しています。
